# 二次开发说明

## 工程结构

```text
src/
  config/        .env 加载、校验、路径规范化、脱敏配置摘要
  core/          日志、错误、请求上下文
  security/      路径白名单、symlink 防逃逸、速率限制
  filesystem/    文件系统业务逻辑和工具实现
  mcp/           MCP Server 创建与工具注册
  http/          Express、CORS、认证、MCP transport
  scripts/       doctor 等脚本
```

## 分层思路

- Transport Layer：`src/http/transports/*`
- HTTP App Layer：`src/http/createApp.ts`、`src/http/middleware.ts`
- API Layer：`src/mcp/tools/register.ts`
- Core Services：`src/config`、`src/core`
- Security Utilities：`src/security`
- Tool Implementation：`src/filesystem`

这个结构便于继续添加 Git、数据库、工单系统等工具，但建议每类工具放独立目录，不要把所有逻辑都塞进一个文件。

## 当前 HTTP 端点

默认端点：

| 路径 | 说明 |
|---|---|
| `/` | 服务运行状态和脱敏配置摘要。 |
| `/health` | 健康检查和脱敏配置摘要。 |
| `/mcp` | Streamable HTTP MCP 入口，ChatGPT 新连接器使用它。 |
| `/sse` | 旧版 SSE 兼容连接入口。 |
| `/messages` | 旧版 SSE 消息入口。 |
| `/debug/config` | 可选调试端点，`ENABLE_DEBUG_ENDPOINTS=1` 时启用。 |

OAuth discovery 路由当前会返回 404：

```text
/.well-known/oauth-authorization-server
/.well-known/openid-configuration
/.well-known/oauth-protected-resource
```

如果要支持 OAuth，需要完整实现 OAuth 授权流程，不是只改文档或路由名称。

## 当前认证模式

`AUTH_MODE` 当前支持：

```text
no-auth
bearer
```

ChatGPT Developer Mode 连接器推荐：

```env
AUTH_MODE=no-auth
```

如果使用 `AUTH_MODE=bearer`，`AUTH_TOKEN` 至少 16 个字符，请求必须带：

```text
Authorization: Bearer 你的AUTH_TOKEN
```

## 新增 MCP 工具步骤

1. 在 `src/filesystem/service.ts` 或新的 service 目录实现业务函数。
2. 在 `src/mcp/tools/register.ts` 注册工具。
3. 给工具写清楚：
   - `title`
   - `description`
   - `inputSchema`
   - `annotations`
4. 路径参数必须调用 `resolveAllowedPath`。
5. 目录遍历必须复用 `shouldSkipDirectoryEntry` 或同等级安全检查。
6. 读取文本文件前要检查大小和二进制特征。
7. 写操作必须调用与 `assertWriteEnabled`、`assertOverwriteEnabled` 等价的检查。
8. 会修改已有文件的操作应支持 `BACKUP_BEFORE_OVERWRITE`。
9. 更新 `docs/工具清单.md`、`docs/安全策略.md` 和相关使用文档。
10. 运行检查命令。

## 工具返回格式

现有工具统一返回：

- `structuredContent`
- `content` 中的 JSON 文本

成功结果通常包含：

```json
{
  "ok": true
}
```

失败结果通常包含：

```json
{
  "ok": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "safe error message"
  }
}
```

新增工具应保持同样风格，避免把 token、secret、绝对敏感内容放进错误信息。

## 路径安全要求

新增任何涉及路径的功能，都必须遵守：

- 路径必须在 `ROOTS` 内。
- `realpath` 后仍必须在 ROOTS 内。
- 不能通过 symlink 逃逸。
- 默认排除规则必须生效。
- 用户传入的额外排除规则只能收紧范围，不应该放开敏感路径。
- 不要读取 `.env`、密钥、数据库、构建产物、依赖目录。

## 写入安全要求

新增写工具时至少要考虑：

- `ALLOW_WRITE=0` 时拒绝。
- 修改已有文件时要求 `ALLOW_OVERWRITE=1`。
- `DRY_RUN_WRITE=1` 时只返回计划，不落盘。
- 写入大小不能超过 `MAX_WRITE_BYTES`。
- 替换类操作要限制替换次数。
- 修改已有文件前按配置备份。
- 不提供删除能力，除非你重新设计完整风险模型。

## 不建议新增 shell 执行

如果确实要加 shell 执行，建议新建独立项目，不要并入这个文件系统连接器。

原因：命令执行和文件读取的风险模型完全不同。加入 shell 执行后，需要重新设计权限、审计、确认、命令白名单、环境变量隔离、输出脱敏和超时控制。

## 修改环境变量 schema

如果新增 `.env` 配置，需要同步更新：

1. `src/config/env.ts` 的 `envSchema`。
2. `AppConfig` 接口。
3. `loadConfig()` 返回值。
4. `publicConfigSummary()` 脱敏摘要。
5. `.env` 示例配置。
6. `docs/环境变量说明.md`。
7. `docs/安全策略.md` 或 `docs/故障排查.md` 中相关说明。

不要把 secret、token、密钥原文放进 `publicConfigSummary()`。

```bash
npm run doctor
```



## MCP Inspector 检查

本地服务启动后运行：

```bash
npm run mcp:inspector
```

或：

```bash
npx @modelcontextprotocol/inspector@latest --server-url http://localhost:2091/mcp --transport http
```

用于确认工具注册、参数 schema 和返回结果是否符合预期。

## 发布前检查

发布或长期公网使用前检查：

- `.env` 不包含真实 secret。
- `ROOTS` 不指向整个磁盘、用户主目录或过大的目录。
- ChatGPT 连接器 URL 以 `/mcp` 结尾。
- ChatGPT 连接器身份验证选择 `No Authentication`，除非你实现了别的认证方式。
- 如果使用 `AUTH_MODE=bearer`，`AUTH_TOKEN` 足够长，且客户端会发送 Authorization header。
- 生产公网时收紧 `CORS_ALLOWED_ORIGINS`。
- 不需要调试时关闭 `ENABLE_DEBUG_ENDPOINTS`。
- 写入能力默认关闭。
- 覆盖前备份保持开启。
- 文档和工具清单已经同步更新。
