# 故障排查

## ChatGPT 连接器提示 No tools listed

按顺序检查：

1. 本地服务是否运行。
2. ngrok / Cloudflare Tunnel 是否运行。
3. ChatGPT 里的 MCP 服务器 URL 是否以 `/mcp` 结尾。
4. 身份验证是否选择 `No Authentication / 无身份验证`。
5. 修改 `.env` 或工具后是否重启了本地服务。
6. ChatGPT 连接器页面是否点击了 Refresh / 刷新。
7. 终端是否有错误日志。

本地健康检查：

```bash
curl http://127.0.0.1:2091/health
```

本地 MCP Inspector 测试：

```bash
npm run mcp:inspector
```

## MCP 服务器 URL 填错

错误：

```text
https://abc123.ngrok-free.app
```

正确：

```text
https://abc123.ngrok-free.app/mcp
```

原因：项目默认 MCP 入口是 `.env` 里的：

```env
MCP_PATH=/mcp
```

如果你改了 `MCP_PATH`，ChatGPT 里的 URL 也要同步改。

## 选择 OAuth 后连接失败

现象：ChatGPT 要求 OAuth 配置、授权失败、发现配置失败，或者服务日志出现 OAuth discovery 相关 404。

原因：当前项目没有实现 OAuth。源码里 OAuth discovery 路由会返回：

```text
OAuth discovery is not configured. Use No Authentication or implement OAuth before enabling it.
```

解决：ChatGPT 连接器里把身份验证改成：

```text
No Authentication / 无身份验证
```

`.env` 保持：

```env
AUTH_MODE=no-auth
```

## 502 / 504

常见原因：

- ngrok 隧道关闭。
- ngrok 转发端口不是 `2091`。
- 本地服务没有启动。
- 服务绑定到了不可访问的 `HOST`。
- 公司网络代理或防火墙拦截。

检查命令：

```bash
curl http://127.0.0.1:2091/health
```

如果本地健康检查失败，先解决本地服务问题。

如果本地健康检查成功，再检查 ngrok 输出是否类似：

```text
Forwarding  https://abc123.ngrok-free.app -> http://localhost:2091
```

## ngrok 地址变了

免费 ngrok 每次重启可能生成新域名。

如果 ngrok 输出的新地址变了，需要回到 ChatGPT 连接器设置里更新：

```text
https://新的-ngrok-域名/mcp
```

然后点击 Refresh / 刷新。

## ROOTS path does not exist

原因：`.env` 里的目录不存在，或者写错了路径。

Windows 建议写：

```env
ROOTS=D:/work/project
```

macOS / Linux 建议写绝对路径：

```env
ROOTS=/Users/me/work/project
```

注意：

- 不要用中文分号。
- 多目录用英文分号 `;`。
- Windows 路径建议使用 `/`。
- 修改 `.env` 后要重启服务。

## ROOTS path is not a directory

原因：`ROOTS` 指向了一个文件，而不是目录。

解决：把 `ROOTS` 改成项目目录路径，例如：

```env
ROOTS=/Users/me/work/my-project
```

不要填到具体文件：

```env
ROOTS=/Users/me/work/my-project/package.json
```

## Path is outside every configured ROOTS directory

原因：工具请求的路径不在 `ROOTS` 白名单内。

解决：

1. 先让 ChatGPT 调用 `list_allowed_roots` 查看允许访问的目录。
2. 确认工具参数里的 `path` 位于某个 ROOT 内。
3. 如果要访问另一个项目，把那个项目目录加入 `ROOTS`。
4. 重启服务。

## Path is blocked by safety pattern

原因：路径命中了 `DEFAULT_EXCLUDE_PATTERNS` 或 `EXTRA_EXCLUDE_PATTERNS`。

常见被拒路径：

- `.env`
- `.git`
- `node_modules`
- `dist`
- `build`
- 密钥、token、credential 相关文件
- 数据库或备份文件

如果是误伤，优先调整业务目录命名或添加更精确的排除规则。不建议删除 `.env`、密钥、token、数据库相关排除项。

## Refusing to read binary-looking file

原因：文件可能是二进制文件，或者文本编码异常。

这个连接器主要用于读取代码和文本文件，不建议放开二进制读取。

如果你只是想知道文件是否存在，可以用 `file_stat`，不要用 `read_file`。

## Write tools are disabled

原因：写入工具被关闭。

创建目录或新文件需要：

```env
ALLOW_WRITE=1
```

修改已有文件还需要：

```env
ALLOW_OVERWRITE=1
```

修改 `.env` 后必须重启服务。

## File already exists

原因：`write_file` 默认不覆盖已有文件。

如果你确实要覆盖已有文件，工具参数需要：

```json
{
  "overwrite": true
}
```

并且 `.env` 中需要：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
```

建议同时保持：

```env
BACKUP_BEFORE_OVERWRITE=1
```

## Existing file modification requires ALLOW_OVERWRITE=1

这些操作会修改已有文件，因此需要 `ALLOW_OVERWRITE=1`：

- 覆盖已有文件
- 追加到已有文件
- `replace_in_file` 精确替换

配置：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
```

修改后重启服务。

## dryRun 返回 true，但文件没变

原因：开启了演练模式。

```env
DRY_RUN_WRITE=1
```

这时写入工具只返回计划，不会真正落盘。

确认计划没问题后改成：

```env
DRY_RUN_WRITE=0
```

然后重启服务。

## AUTH_MODE=bearer 后连接失败

如果你把 `.env` 改成：

```env
AUTH_MODE=bearer
```

则请求必须带：

```text
Authorization: Bearer 你的AUTH_TOKEN
```

ChatGPT Developer Mode 连接器通常建议保持：

```env
AUTH_MODE=no-auth
```

并在 ChatGPT 里选择：

```text
No Authentication / 无身份验证
```

## MCP Inspector 连接失败

确认本地服务在运行：

```bash
curl http://127.0.0.1:2091/health
```

然后执行：

```bash
npx @modelcontextprotocol/inspector@latest --server-url http://localhost:2091/mcp --transport http
```

如果 Inspector 能连而 ChatGPT 不能连，问题通常在：

- ngrok HTTPS 地址过期或填错
- ChatGPT 连接器 URL 少了 `/mcp`
- ChatGPT 连接器选了 OAuth
- 修改配置后没有 Refresh

## 修改 `.env` 后没生效

`.env` 只在服务启动时读取。

解决：

1. 停止 `npm run dev`。
2. 重新运行 `npm run dev`。
3. 回到 ChatGPT 连接器里点击 Refresh。
4. 新开一个对话测试。

## 如何查看当前脱敏配置

本地访问：

```text
http://127.0.0.1:2091/health
```

如果 `ENABLE_DEBUG_ENDPOINTS=1`，还可以访问：

```text
http://127.0.0.1:2091/debug/config
```

这些端点不会返回 `AUTH_TOKEN` 或 secret。
