# 二次开发说明

## 工程结构

```text
src/
  config/        .env 加载、校验、脱敏摘要
  core/          日志、错误、请求上下文
  security/      路径白名单、symlink 防逃逸、速率限制
  filesystem/    文件系统业务逻辑
  mcp/           MCP Server 创建与工具注册
  http/          Express、CORS、认证、MCP transport
  scripts/       doctor 等脚本
```

## 分层思路

- Transport Layer：`src/http/transports/*`
- API Layer：`src/mcp/tools/register.ts`
- Core Services：`src/config`、`src/core`
- Security Utilities：`src/security`
- Tool Implementation：`src/filesystem`

这个结构便于继续添加 Git、数据库、工单系统等工具，但建议每类工具独立目录，不要把所有逻辑写进一个文件。

## 新增工具步骤

1. 在 `src/filesystem/service.ts` 或新的 service 目录写业务函数。
2. 在 `src/mcp/tools/register.ts` 注册工具。
3. 给工具写清楚：
   - `title`
   - `description`
   - `inputSchema`
   - `annotations`
4. 对所有路径调用 `resolveAllowedPath`。
5. 对写操作调用 `assertWriteEnabled` 类似逻辑。
6. 更新 `docs/工具清单.md`。

## 不建议新增 shell 执行

如果确实要加 shell 执行，建议新建独立项目，不要并入这个文件系统连接器。命令执行和文件读取的风险模型完全不同。

## 代码检查

```bash
npm run build
npm test
npm run doctor
```

## 发布前检查

- `.env` 不包含真实 secret。
- `ROOTS` 不指向整个磁盘。
- `AUTH_MODE` 符合你的连接器认证模式。
- 生产公网时收紧 `CORS_ALLOWED_ORIGINS`。
- 写入能力默认关闭。
