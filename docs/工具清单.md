# 工具清单

## 通用规则

所有工具都受 `.env` 配置限制：

- 路径必须位于 `ROOTS` 白名单内。
- 默认会跳过 `.env`、密钥、数据库、依赖目录、构建产物等敏感路径。
- 读取类工具默认只处理 UTF-8 文本文件。
- 写入类工具默认关闭，需要显式开启 `ALLOW_WRITE`。
- 修改已有文件还需要 `ALLOW_OVERWRITE=1`。
- `local_agent_run` 默认关闭，需要 `LOCAL_AGENT_ENABLED=1`。
- agent 内部修改已有文件比直接工具更严格：必须先完整 `read_file`，且文件未变旧。
- agent 内部安全 Bash 默认关闭，需要 `AGENT_BASH_ENABLED=1` 和精确 `AGENT_BASH_ALLOWLIST`。
- 如果 `ALLOW_RELATIVE_PATHS=1`，相对路径会按第一个 ROOT 解析。

建议每个新对话先调用：

```text
list_allowed_roots
server_config_summary
```

## list_allowed_roots

用途：查看服务器允许访问哪些本地目录、当前传输方式、认证方式、写入开关和安全限制。

参数：无。

建议：每个新对话先调用它，确认 ChatGPT 实际能访问哪些目录。

返回内容包括：

- `allowedRoots`
- `auth`
- `transport`
- `writePolicy`
- `limits`
- `defaultExcludePatterns`
- `extraExcludePatterns`

## server_config_summary

用途：查看脱敏配置摘要。

参数：无。

它不会返回 `AUTH_TOKEN` 或 secret。

适合用来确认：

- `/mcp` 路径
- 是否启用旧版 SSE
- 当前认证模式
- 写入开关
- 读取和搜索限制
- ROOTS 摘要

## local_agent_run

用途：运行一个受控的本地写代码代理循环。ChatGPT 只调用这个高层工具，服务端内部再由 agent 使用受限文件工具和可选安全 Bash。

默认关闭。需要：

```env
LOCAL_AGENT_ENABLED=1
LOCAL_AGENT_MODEL_BASE_URL=https://api.openai.com/v1
LOCAL_AGENT_MODEL_API_KEY=你的本机私有Key
LOCAL_AGENT_MODEL_NAME=gpt-4.1
```

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `prompt` | 是 | 给本地 agent 的任务或问题。 |
| `path` | 否 | ROOTS 内的工作目录，默认第一个 ROOT。 |
| `sessionId` | 否 | 继续一个进程内存里的 agent session。 |
| `maxTurns` | 否 | 本次最大模型轮次，不能超过 `LOCAL_AGENT_MAX_TURNS`。 |
| `maxToolCalls` | 否 | 本次最大工具调用数，不能超过 `LOCAL_AGENT_MAX_TOOL_CALLS`。 |
| `dryRun` | 否 | `true` 时 agent 写入工具只演练，安全 Bash 也不实际执行。 |

返回内容包括：

- `sessionId`
- `finalText`
- `stopReason`
- `turns`
- `toolCalls`
- `filesRead`
- `filesChanged`
- `bashCommands`
- `warnings`
- `usage`

安全限制：

- 所有路径仍然必须在 ROOTS 内。
- 修改已有文件前必须先完整读取该文件。
- 如果读取后文件被外部修改，agent 写入会被 stale-read 检查拒绝。
- 内部没有删除工具。
- 安全 Bash 默认关闭；开启后也只允许精确匹配 allowlist 的命令。

示例：

```json
{
  "prompt": "阅读 README.md 和 package.json，总结项目用途，不要修改文件。",
  "path": ".",
  "dryRun": true
}
```

## project_overview

用途：快速识别项目关键文件、技术栈线索、`package.json` 摘要和推荐下一步读取文件。

适合第一次读取项目。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的项目目录。可传绝对路径，也可传相对第一个 ROOT 的路径。 |
| `depth` | 否 | 扫描深度，默认 `4`，最大不超过 `MAX_TREE_DEPTH`。 |
| `maxFiles` | 否 | 最多采样文件数，最大不超过 `MAX_PROJECT_OVERVIEW_FILES`。 |
| `includePatterns` | 否 | 当前实现中作为本次扫描的额外路径安全过滤模式传入。 |

示例：

```json
{
  "path": ".",
  "depth": 4,
  "maxFiles": 80
}
```

常见返回内容：

- `technologyHints`
- `keyFiles`
- `recommendedNextReads`
- `packageJson`
- `skipped`

## directory_tree

用途：读取目录结构。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的目录路径。 |
| `depth` | 否 | 目录深度，默认 `DEFAULT_TREE_DEPTH`，最大 `MAX_TREE_DEPTH`。 |
| `maxEntries` | 否 | 最大返回条目数，最大 `MAX_TREE_ENTRIES`。 |
| `excludePatterns` | 否 | 本次调用额外排除规则，使用 minimatch。 |

示例：

```json
{
  "path": ".",
  "depth": 3,
  "maxEntries": 500,
  "excludePatterns": ["**/vendor/**"]
}
```

返回内容包括目录树、跳过条目数量和跳过原因。

## file_stat

用途：读取文件或目录元信息。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的文件或目录路径。 |

返回内容包括：

- 类型：`file`、`directory`、`symlink`、`other`
- 大小
- 创建时间
- 修改时间
- 访问时间
- 是否只读

适合在读取文件内容前先确认路径是否存在、大小是否合理。

## read_file

用途：读取单个 UTF-8 文本文件。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的文件路径。 |
| `maxBytes` | 否 | 本次最多读取字节数，不能超过 `MAX_READ_BYTES`。 |

限制：

- 不读取二进制文件。
- 不读取敏感路径。
- 大文件会按 `maxBytes` 或 `MAX_READ_BYTES` 截断。

示例：

```json
{
  "path": "README.md",
  "maxBytes": 65536
}
```

## read_many_files

用途：一次读取多个文本文件。

适合读取 `AGENTS.md`、`README.md`、`package.json`、入口文件、关键配置文件等。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `paths` | 是 | 文件路径数组，数量不能超过 `MAX_READ_MANY_FILES`。 |
| `maxBytesPerFile` | 否 | 单文件读取上限，不能超过 `MAX_READ_BYTES`。 |
| `maxTotalBytes` | 否 | 本次总读取上限，不能超过 `MAX_READ_MANY_TOTAL_BYTES`。 |

示例：

```json
{
  "paths": ["AGENTS.md", "README.md", "package.json"],
  "maxBytesPerFile": 65536,
  "maxTotalBytes": 196608
}
```

## search_files

用途：搜索目录下文本内容。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的目录路径。 |
| `query` | 是 | 要搜索的字面量文本或 JavaScript 正则。 |
| `mode` | 否 | `literal` 或 `regex`，默认 `literal`。 |
| `includeGlob` | 否 | 只搜索匹配的文件，例如 `**/*.{ts,vue,md}`。 |
| `excludePatterns` | 否 | 本次调用额外排除规则。 |
| `caseSensitive` | 否 | 是否大小写敏感，默认 `false`。 |
| `maxFiles` | 否 | 最大扫描文件数，不能超过 `MAX_SEARCH_FILES`。 |
| `maxResults` | 否 | 最大返回结果数，不能超过 `MAX_SEARCH_RESULTS`。 |

字面量搜索示例：

```json
{
  "path": ".",
  "query": "MCP_PATH",
  "mode": "literal",
  "includeGlob": "**/*.{ts,md,json}"
}
```

正则搜索示例：

```json
{
  "path": ".",
  "query": "registerTool\\(",
  "mode": "regex",
  "includeGlob": "src/**/*.ts"
}
```

## create_directory

用途：创建目录。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内要创建的目录路径。 |

需要：

```env
ALLOW_WRITE=1
```

如果 `DRY_RUN_WRITE=1`，只返回计划，不真正创建目录。

## write_file

用途：创建或覆盖 UTF-8 文本文件。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的文件路径。 |
| `content` | 是 | UTF-8 文本内容。 |
| `overwrite` | 否 | 默认 `false`。覆盖已有文件时必须显式传 `true`。 |

创建新文件需要：

```env
ALLOW_WRITE=1
```

覆盖已有文件需要：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
```

并且工具参数需要：

```json
{
  "overwrite": true
}
```

如果 `BACKUP_BEFORE_OVERWRITE=1`，覆盖前会备份已有文件。

## append_file

用途：追加 UTF-8 文本到文件末尾。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的文件路径。 |
| `content` | 是 | 要追加的 UTF-8 文本。 |
| `createIfMissing` | 否 | 默认 `false`。文件不存在时是否创建。 |

创建新文件需要：

```env
ALLOW_WRITE=1
```

追加到已有文件需要：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
```

如果 `BACKUP_BEFORE_OVERWRITE=1`，追加已有文件前会备份。

## replace_in_file

用途：对已有 UTF-8 文本文件做精确文本替换。

适合小范围代码修改，不适合大范围重写。

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | ROOTS 内的已有文件路径。 |
| `oldText` | 是 | 要查找的精确旧文本，不能为空。 |
| `newText` | 是 | 替换后的文本。 |
| `replaceAll` | 否 | 默认 `false`，只替换第一个匹配；`true` 时替换全部匹配。 |

需要：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
```

限制：

- 文件大小不能超过 `MAX_READ_BYTES`。
- 替换后大小不能超过 `MAX_WRITE_BYTES`。
- `replaceAll=true` 时替换次数不能超过 `MAX_REPLACE_OCCURRENCES`。
- 如果 `BACKUP_BEFORE_OVERWRITE=1`，替换前会备份。

示例：

```json
{
  "path": "src/index.ts",
  "oldText": "oldValue",
  "newText": "newValue",
  "replaceAll": false
}
```

## 推荐调用顺序

第一次理解项目：

```text
list_allowed_roots
server_config_summary
project_overview
directory_tree
read_many_files
search_files
```

准备让 agent 完成一段代码任务：

```text
local_agent_run
```

直接工具准备修改文件：

```text
file_stat
read_file
replace_in_file
```

需要新增文件：

```text
create_directory
write_file
```

## 不存在的工具能力

本项目不提供：

- 任意 shell 执行；只有 `local_agent_run` 内部的 `safe_bash`，且默认关闭、allowlist-only
- 删除文件
- 删除目录
- 任意磁盘读取
- 浏览器数据读取
- 数据库直连
