# 安全策略

## 安全边界

本项目的安全模型是：只把 `.env` 里 `ROOTS` 指定的本地目录，通过受控 MCP 工具暴露给 ChatGPT。

它不会让 ChatGPT 直接访问整个硬盘。每次路径访问都会经过白名单、真实路径、安全排除、文件类型和大小限制检查。

## 默认只读

`.env` 默认建议保持：

```env
ALLOW_WRITE=0
ALLOW_OVERWRITE=0
```

这意味着 ChatGPT 只能读取允许范围内的安全文本文件，不能创建、追加、替换或覆盖文件。

## ROOTS 白名单

所有路径必须在 `.env` 的 `ROOTS` 里。路径会经过两层检查：

1. 词法路径必须位于某个 ROOT 内。
2. `realpath` 后仍然必须位于同一个 ROOT 内，防止 symlink 逃逸。

安全建议：

- ROOTS 精确到项目目录。
- 不要设置为 `/`、`C:/`、`D:/`。
- 不要设置为用户主目录。
- 不建议设置为整个 Desktop。
- 多个项目目录用英文分号 `;` 分隔。

## 相对路径规则

当 `ALLOW_RELATIVE_PATHS=1` 时，工具参数里的相对路径会按第一个 ROOT 解析。

例如：

```env
ROOTS=/Users/me/work/my-project
ALLOW_RELATIVE_PATHS=1
```

那么工具里传：

```json
{ "path": "src" }
```

会解析到：

```text
/Users/me/work/my-project/src
```

## 默认敏感路径排除

默认排除：

- `.env`、`.env.*`
- `*secret*`、`*secrets*`
- `*credential*`、`*credentials*`
- `*token*`
- `*.pem`、`*.key`、`*.p12`、`*.pfx`
- `id_rsa`、`id_ed25519`
- `.ssh`、`.aws`、`.azure`、`.gcloud`
- `.git`、`.svn`、`.hg`
- `node_modules`、`dist`、`build`
- `.next`、`.nuxt`、`.turbo`
- `coverage`、`.cache`、`tmp`、`temp`
- sqlite、db、dump、bak 等数据库或备份文件

不建议为了方便而删除这些敏感排除项。

如果业务目录被误伤，优先通过调整目录命名或添加更精确的 `EXTRA_EXCLUDE_PATTERNS` 解决。

## 文件类型和二进制拒绝

读取和搜索会检查：

- 文件扩展名
- 文件大小
- 二进制特征
- 安全排除规则

二进制文件、图片、压缩包、数据库、密钥文件等默认会被拒绝。

本项目主要面向代码、配置说明、Markdown、JSON、TypeScript、JavaScript 等文本项目文件。

## 认证策略

ChatGPT Developer Mode 连接器建议使用：

```text
No Authentication / 无身份验证
```

对应 `.env`：

```env
AUTH_MODE=no-auth
```

当前项目没有实现 OAuth。选择 OAuth 会导致 OAuth discovery 失败。

如果你给自己的客户端使用，可以改成 Bearer token：

```env
AUTH_MODE=bearer
AUTH_TOKEN=至少16位的随机字符串
```

但改成 Bearer 后，客户端必须发送：

```text
Authorization: Bearer 你的AUTH_TOKEN
```

## 公网暴露风险

通过 ngrok / Cloudflare Tunnel 暴露后，知道公网 URL 的人就可能访问你的 MCP 服务。

建议：

- 不要公开分享 ngrok URL。
- 不用时关闭 ngrok。
- ROOTS 不要设太大。
- 首次使用保持只读。
- 生产或长期公网暴露时收紧认证、CORS、调试端点和访问来源。

## CORS 和速率限制

开发期可以使用：

```env
CORS_ALLOWED_ORIGINS=*
HTTP_RATE_LIMIT_WINDOW_MS=60000
HTTP_RATE_LIMIT_MAX=240
```

如果是长期公网服务，建议把 `CORS_ALLOWED_ORIGINS` 改成明确来源，并保留速率限制。

`HTTP_RATE_LIMIT_WINDOW_MS=0` 或 `HTTP_RATE_LIMIT_MAX=0` 表示关闭速率限制。

## 调试端点

当 `ENABLE_DEBUG_ENDPOINTS=1` 时，可以访问：

```text
/debug/config
```

它只返回脱敏配置摘要，不返回 token 或 secret。但生产公网环境仍建议关闭：

```env
ENABLE_DEBUG_ENDPOINTS=0
```

## 写入分级

| 场景 | 所需配置 |
|---|---|
| 只读 | `ALLOW_WRITE=0` |
| 创建目录 | `ALLOW_WRITE=1` |
| 创建新文件 | `ALLOW_WRITE=1` |
| 追加到已有文件 | `ALLOW_WRITE=1` + `ALLOW_OVERWRITE=1` |
| 覆盖已有文件 | `ALLOW_WRITE=1` + `ALLOW_OVERWRITE=1` |
| 精确替换已有文件 | `ALLOW_WRITE=1` + `ALLOW_OVERWRITE=1` |
| 只演练不落盘 | `DRY_RUN_WRITE=1` |

## 覆盖前备份

建议保持：

```env
BACKUP_BEFORE_OVERWRITE=1
BACKUP_DIR=.super-local-link-backups
```

覆盖、追加已有文件、精确替换时，会在对应 ROOT 下创建备份。

如果 `DRY_RUN_WRITE=1`，写操作只返回计划，不会真正落盘，也不会创建备份。

## 不提供的能力

本项目故意不提供：

- 执行 shell 命令
- 删除文件
- 删除目录
- 读取任意磁盘
- 读取浏览器数据
- 读取密钥文件
- 读取数据库文件

如果你确实需要命令执行，建议做成独立项目，不要并入这个文件系统连接器。

## 推荐安全配置

首次连接和读取项目：

```env
AUTH_MODE=no-auth
ALLOW_WRITE=0
ALLOW_OVERWRITE=0
ENABLE_DEBUG_ENDPOINTS=1
```

准备让 ChatGPT 修改代码前，先演练：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
DRY_RUN_WRITE=1
BACKUP_BEFORE_OVERWRITE=1
```

确认工具调用计划无误后，再落盘：

```env
DRY_RUN_WRITE=0
```
