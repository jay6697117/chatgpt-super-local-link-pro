# 详细使用说明

## 1. 这是什么

`ChatGPT Super Local Link Pro` 是一个本地运行的 Node.js / TypeScript Remote MCP Server。它把你指定的本地项目目录暴露成一组受控 MCP 工具，让 ChatGPT 可以读取项目结构、搜索代码、读取文本文件，并在你明确开启写入后创建或修改文件。

它不是远程虚拟机，也不是让 ChatGPT 直接访问整个硬盘。完整链路是：

```text
ChatGPT
  ↓ HTTPS MCP
ngrok / Cloudflare Tunnel 公网地址
  ↓
本机 Node.js MCP Server
  ↓
.env 中 ROOTS 白名单目录
```

ChatGPT 只能访问 `ROOTS` 白名单内、且没有被安全规则排除的路径。

## 2. 环境要求

- Node.js 20.11 或更高版本
- npm
- ngrok 或 Cloudflare Tunnel
- ChatGPT 中开启 Developer Mode

Windows 用户建议使用 PowerShell。macOS / Linux 用户可以使用系统终端。

## 3. 安装

进入项目目录后运行：

```bash
npm install
npm run doctor
```

如果 `doctor` 成功，会输出脱敏后的配置摘要。它会检查：

- `ROOTS` 是否存在
- `ROOTS` 是否是目录
- `MCP_PATH` 是否合法
- `AUTH_MODE=bearer` 时 `AUTH_TOKEN` 是否足够长
- 读取和树形扫描限制是否合理

## 4. 配置 ROOTS

`ROOTS` 是本项目最重要的安全边界。只把你想让 ChatGPT 访问的项目目录放进去。

编辑 `.env`：

```env
ROOTS=/Users/me/work/my-project
```

Windows 示例：

```env
ROOTS=D:/work/my-project
```

多个目录用英文分号 `;` 分隔：

```env
ROOTS=/Users/me/work/project-a;/Users/me/work/project-b
```

Windows 多目录示例：

```env
ROOTS=D:/work/project-a;D:/work/project-b
```

注意：

- Windows 路径建议写成 `D:/work/project`，不要写成 `D:\work\project`。
- 不要把 `C:/`、`D:/` 整个盘符作为 ROOTS。
- 不要把 `/` 作为 ROOTS。
- 不要把用户主目录整体作为 ROOTS。
- 不建议把整个 Desktop 作为 ROOTS，最好精确到某一个项目目录。
- `.env` 修改后必须重启服务。

## 5. 启动本地服务

开发模式：

```bash
npm run dev
```

生产模式：

```bash
npm run build
npm run start
```

默认本地地址：

```text
http://127.0.0.1:2091
```

常用端点：

```text
http://127.0.0.1:2091/health
http://127.0.0.1:2091/mcp
```

其中 `/mcp` 是 ChatGPT 连接器入口。

## 6. 暴露 HTTPS 地址

ChatGPT 连接器需要公网 HTTPS 地址。本地开发可以使用 ngrok：

```bash
ngrok http 2091
```

看到类似输出：

```text
Forwarding  https://abc123.ngrok-free.app -> http://localhost:2091
```

那么 ChatGPT 连接器里的 MCP 服务器 URL 填：

```text
https://abc123.ngrok-free.app/mcp
```

必须带 `/mcp`。

## 7. 在 ChatGPT 中添加连接器

1. 打开 ChatGPT 设置。
2. 进入 Apps / Connectors。
3. 开启 Developer Mode。
4. 点击 Create / 新建。
5. 填写：

```text
Name / 名称：超级本地链接 Pro
Description / 描述：安全读取和可选编辑本机 ROOTS 白名单项目目录
MCP 服务器 URL：https://你的域名/mcp
Authentication / 身份验证：No Authentication / 无身份验证
```

不要选择 OAuth。当前项目没有实现 OAuth；选择 OAuth 会导致 ChatGPT 发现 OAuth 配置失败。

## 8. 第一次对话建议

首次连接建议只读，不要直接让 ChatGPT 修改文件。

可以这样问：

```text
使用“超级本地链接 Pro”读取我的项目。先调用 list_allowed_roots，再对我的项目目录调用 project_overview 和 directory_tree。不要读取 .env、密钥、数据库、node_modules、dist、.git。第一轮只输出项目结构、关键文件、技术栈判断和建议下一步读取哪些文件，不做任何写入。
```

## 9. 写入模式

默认只读：

```env
ALLOW_WRITE=0
ALLOW_OVERWRITE=0
```

允许创建新文件/目录，但不允许修改已有文件：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=0
```

允许修改已有文件：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
BACKUP_BEFORE_OVERWRITE=1
```

首次开启写入时建议先演练：

```env
ALLOW_WRITE=1
ALLOW_OVERWRITE=1
DRY_RUN_WRITE=1
```

确认工具返回的计划符合预期后，再改成：

```env
DRY_RUN_WRITE=0
```

每次修改 `.env` 后都要重启服务。

## 10. 推荐工作流

读取阶段：

```text
先调用 list_allowed_roots、server_config_summary、project_overview、directory_tree。重点查看 AGENTS.md、README.md、package.json、src 入口、docs、scripts。不要读取 .env、secrets、数据库、构建产物和依赖目录。
```

分析阶段：

```text
根据目录结构和关键文件，输出技术栈判断、模块划分、可能入口、构建脚本、下一轮建议读取文件。不要写入。
```

修改阶段：

```text
在修改前先说明计划。优先使用 replace_in_file 做小范围精确替换。不要覆盖整文件，除非我明确要求。
```

验收阶段：

```text
修改后说明改了哪些文件、为什么改、如何验证。如果需要运行命令，先告诉我命令和目的。
```

## 11. 常用本地检查

```bash
npm run doctor
npm run build
npm test
```

或者一次执行：

```bash
npm run check
```

## 12. 关闭服务

本地服务终端里按：

```text
Ctrl+C
```

如果用了 ngrok，也在 ngrok 终端里按 `Ctrl+C`。停止 ngrok 后，公网地址会失效。
